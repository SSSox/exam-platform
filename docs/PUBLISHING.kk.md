# GitHub Pages-ке жариялау

Қолданба мен банктер бөлек жарияланады, әрқайсысы өз репозиторийінен:

- Банктер репозиторийі `index.json`, `nodes/` және `banks/` бар статикалық сайтқа айналады.
- Қолданба кірістірілген мазмұнсыз құрастырылады және іске қосылғанда банктерді осы сайттың мекенжайынан жүктейді.

Құжаттағы репозиторий мекенжайлары шартты. Төменде `<пайдаланушы>` GitHub-тағы сіздің аккаунтыңыз немесе ұйымыңыз, ал `<банктер-репозиторийі>` мен `<код-репозиторийі>` сіздің репозиторийлеріңіздің атаулары. Жобаның өз банктерінің мекенжайы код репозиторийінің түбіріндегі `content-sources.json` файлында жазылған; өз көшірмеңізді жарияласаңыз, оны өзіңіздікіне ауыстырыңыз.

## Алдын ала не қажет

- GitHub-та екі репозиторий: кодтікі (`exam-platform`) және банктердікі (`exam-content`). Төмендегі банктер үлгісі пәрмен жолын код репозиторийінен алады; код репозиторийі жабық болса, қолжетімділік токені қажет болады.
- Әр репозиторийдің баптауларында: Settings, Pages, Source: GitHub Actions.
- Қолданба беті мазмұнды тек `https://*.github.io` және `https://cdn.jsdelivr.net` мекенжайларынан жүктейді (`apps/ui/index.html` ішіндегі CSP). Өз доменіңіздегі сайт үшін доменді осы файлдағы `connect-src` тізіміне қосып, қолданбаны қайта құрастырыңыз.
- Банктер хостингі файлдарды басқа көзден оқуға рұқсат беруі керек (CORS), өйткені қолданба басқа мекенжайда орналасқан. Алғашқы жариялаудан кейін қолданбаны ашып, браузер консолін қараңыз: CORS қатесі хостингтің рұқсат бермейтінін білдіреді.

## Жариялау алдындағы тексеру

Код репозиторийінің түбірінен, банктер қалтасында (жолын өзіңіз көрсетіңіз):

```bash
node packages/content-tools/src/cli.ts validate <банктер-қалтасы>
node packages/content-tools/src/cli.ts compile <банктер-қалтасы> <нәтиже-қалтасы>
```

`validate` банктер мен сұрақтардың санын немесе қателер тізімін шығарады. `compile` мазмұнды өзі тексереді және қате болса ештеңе жазбайды. Жинау алдында `compile` нәтиже қалтасын өшіреді, сондықтан бұл қалта банктер қалтасының ішінде болмауы, оны қамтымауы және онымен сәйкес келмеуі тиіс. Ол тек бос қалтаны немесе алдыңғы жинақты (ішінде тек `nodes`, `banks`, `index.json`) өшіреді; кез келген басқа қалта болса, пәрмен ештеңе өшірмей тоқтайды.

## Банктерді жариялау

Банктер репозиторийі түгелдей жарияланады: workflow мазмұнды тексереді, `compile` пәрменімен жинайды және нәтижені Pages-ке шығарады. Жинақ қалтасы сайттың түбіріне айналады, сондықтан қолданбаға арналған мекенжай мынадай:

```
https://<пайдаланушы>.github.io/<банктер-репозиторийі>
```

Банктер репозиторийіне арналған `.github/workflows/pages.yml` үлгісі.

> Үлгі іске қосылып көрілмеген. Репозиторий мекенжайларын өзіңіздікімен ауыстырыңыз, әрекеттердің нұсқаларын ағымдағыларымен салыстырып тексеріңіз.

```yaml
name: Publish content

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: true

jobs:
  publish:
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      # Банктер осы репозиторийдің түбірінде жатыр; оларды content ішкі қалтасына саламыз.
      - uses: actions/checkout@v4
        with:
          path: content

      # Код тек пәрмен жолы үшін керек. Өз код репозиторийіңізді қойыңыз.
      - uses: actions/checkout@v4
        with:
          repository: <пайдаланушы>/<код-репозиторийі>
          ref: main
          path: code

      - uses: actions/setup-node@v4
        with:
          node-version: 26

      - name: Install the command line
        working-directory: code
        run: npm ci

      - name: Validate
        run: node code/packages/content-tools/src/cli.ts validate content

      # site қалтасы content ішінде емес, оның жанында жатыр: compile нәтиже қалтасын өшіреді.
      - name: Compile
        run: node code/packages/content-tools/src/cli.ts compile content site

      - uses: actions/configure-pages@v5
      - uses: actions/upload-pages-artifact@v3
        with:
          path: site
      - id: deployment
        uses: actions/deploy-pages@v4
```

Алғашқы іске қосудан кейін `https://<пайдаланушы>.github.io/<банктер-репозиторийі>/index.json` мекенжайын ашыңыз: жауапта `version`, `kinds` және `roots` өрістері бар JSON болуы керек.

## Қолданбаны жариялау

Қолданба кірістірілген мазмұнсыз (`EXAM_CONTENT_DIR=none`) және банктер сайтының мекенжайымен құрастырылады. Мекенжай код репозиторийінің түбіріндегі `content-sources.json` файлында тұр (`urls` өрісі), ал `VITE_CONTENT_URLS` айнымалысы оны бір құрастыруға ауыстырады. Екеуі де құрастыру кезінде оқылып, кодқа кіріктіріледі, сондықтан мекенжайды өзгерту үшін қолданбаны қайта құрастыру керек. Нәтиже `apps/ui/dist` ішінде жатыр, ондағы жолдар салыстырмалы, сондықтан сайт `/<код-репозиторийі>/` ішкі қалтасында да жұмыс істейді. Беттердің мекенжайлары `#` арқылы құрылған, сондықтан қайта бағыттауды баптаудың қажеті жоқ.

Жергілікті түрде, код репозиторийінің түбірінен:

```bash
EXAM_CONTENT_DIR=none VITE_CONTENT_URLS=https://<пайдаланушы>.github.io/<банктер-репозиторийі> npm --prefix apps/ui run build
```

PowerShell-де:

```powershell
$env:EXAM_CONTENT_DIR = "none"
$env:VITE_CONTENT_URLS = "https://<пайдаланушы>.github.io/<банктер-репозиторийі>"
npm --prefix apps/ui run build
```

Код репозиторийіне арналған `.github/workflows/pages.yml` үлгісі.

> Үлгі іске қосылып көрілмеген. Репозиторий мекенжайларын өзіңіздікімен ауыстырыңыз, әрекеттердің нұсқаларын ағымдағыларымен салыстырып тексеріңіз.

```yaml
name: Publish app

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: true

jobs:
  publish:
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: 26
          cache: npm

      - run: npm ci

      - name: Build the app without embedded content
        run: npm --prefix apps/ui run build
        env:
          EXAM_CONTENT_DIR: none
          # Банктер сайтының мекенжайы (соңында слэшсіз). Өзіңіздікін қойыңыз.
          VITE_CONTENT_URLS: https://<пайдаланушы>.github.io/<банктер-репозиторийі>

      - uses: actions/configure-pages@v5
      - uses: actions/upload-pages-artifact@v3
        with:
          path: apps/ui/dist
      - id: deployment
        uses: actions/deploy-pages@v4
```

Қолданба `https://<пайдаланушы>.github.io/<код-репозиторийі>/` мекенжайында қолжетімді болады.

## Деректер қалай жаңартылады

- Банкті түзету: банктер репозиторийіне коммит жасайсыз, workflow сайтты қайта жинайды. Қолданба іске қосылғанда `index.json` файлын кэшсіз қайта оқиды, жаңа нұсқаны көріп, тек хэші өзгерген файлдарды жүктейді. Қолданбаны қайта құрастырудың қажеті жоқ.
- Банктер сайтының мекенжайын ауыстыру немесе екінші айнаның пайда болуы: `content-sources.json` файлын (немесе бір құрастыру үшін `VITE_CONTENT_URLS` мәнін) түзетіп, қолданбаны қайта құрастыру керек.
- Банктер мекенжайлары жауап бермейді: қолданба соңғы сақталған каталогты «Желі жоқ, сақталған деректер көрсетіліп тұр» белгісімен көрсетеді, ал бұрын ашылған банктер мен түйіндерді кэштен оқиды. Құрылғыда ештеңе сақталмаған болса, ол `index.json` файлын кірістірілген көшірмеден сол белгімен алады. Көшірмесіз құрастырмада (`EXAM_CONTENT_DIR=none`) желісіз алғашқы іске қосу жүктеу қатесін көрсетеді.

## Windows орнатқышы

Жұмыс үстелі нұсқасы `apps/desktop` ішінен `npx tauri build` пәрменімен құрастырылады және интерфейстің дәл сол құрастырмасын іске қосады. Банктері кірістірілген орнатқыш қажет болса, оны `EXAM_CONTENT_DIR=none` көрсетпей құрастырыңыз: мазмұн жанындағы `exam-content` қалтасынан немесе `EXAM_CONTENT_DIR` айнымалысынан алынады. `VITE_CONTENT_URLS` болса, орнатқыш банктерді желі арқылы жаңарта алады.

## Веб-нұсқадағы Windows және Android сілтемелері

Веб-нұсқа орнатқыштарға сілтемелерді пәндер тізімінің астындағы жолда және баптаулардағы «Қолданба» карточкасында көрсетеді. Windows және Android қолданбаларында бұл сілтемелер жоқ. Android телефонында алдымен Android сілтемесі тұрады.

Мекенжайлар код репозиторийінің түбіріндегі `downloads.json` файлында жатады (`windows` және `android` өрістері) және банктер мекенжайы сияқты құрастыру кезінде кодқа енгізіледі. `VITE_DOWNLOAD_WINDOWS` және `VITE_DOWNLOAD_ANDROID` айнымалылары оларды бір құрастыруға ауыстырады. `none` мәні сілтемені алып тастайды (`downloads.json` ішінде бос жол да жарайды), екі сілтеме де болмаса, блок көрсетілмейді. `https://` деп басталмайтын мекенжай құрастыруды тоқтатады. Жобаның `downloads.json` файлында оның өз репозиторийі жазылған; өз көшірмеңізді жарияласаңыз, мекенжайларды ауыстырыңыз, `none` қойыңыз немесе файлды жойыңыз.

Әдепкі мекенжайлар код репозиторийінің соңғы релизіндегі файлдарға апарады:

```
https://github.com/<пайдаланушы>/<код-репозиторийі>/releases/latest/download/exam-trainer-windows-setup.exe
https://github.com/<пайдаланушы>/<код-репозиторийі>/releases/latest/download/exam-trainer-android.apk
```

Мұндай релиз болмайынша, сілтемелер 404 қайтарады. Релизді шығару «Релизді шығару» бөлімінде сипатталған.

## Қолданбаларды автоматты жаңарту

Windows және Android қолданбалары күніне бір рет, іске қосылғаннан кейін бірнеше секундтан соң немесе қолданбаға қайта оралғанда код репозиторийінің соңғы релизінен `latest.json` файлын оқиды:

```
https://github.com/<пайдаланушы>/<код-репозиторийі>/releases/latest/download/latest.json
```

Мекенжай `apps/desktop/src-tauri/tauri.conf.json` ішіндегі `plugins.updater.endpoints` өрісінен алынады және құрастыру кезінде кодқа енгізіледі, APK-ға да. `latest.json` ішіндегі нұсқа орнатылғаннан жоғары болса, баптауларда және пәндер тізімінің астында файл өлшемі көрсетілген «Жаңарту» түймесі пайда болады. Жүктеу тек түймені басқанда басталады. Баптауларда «Жаңартуларды тексеру» түймесі де бар. Веб-нұсқаға автоматты жаңарту керек емес: әр кірген сайын сайттың жаңа құрастырмасы ашылады.

Орнатудан бұрын қолданба жүктелген файлды тексереді:

- Windows орнатқыштың қолтаңбасын `plugins.updater.pubkey` ішіндегі ашық кілтпен тексереді, ал қол қойылған нұсқа `latest.json` ішіндегі нұсқамен сәйкес келуі керек. Содан кейін орнатқыш сұрақсыз жұмыс істейді (орнату барысын көрсететін терезе ашылады), қолданба жабылып, жаңа нұсқамен қайта іске қосылады.
- Android өлшемді және SHA-256 мәнін `latest.json` файлымен салыстырады, содан кейін пакет атауын, APK нұсқасын (ол `latest.json` ішіндегі нұсқамен сәйкес келуі керек), құрастыру нөмірін (ол орнатылғаннан жоғары болуы керек) және APK қол қою сертификатын тексереді: ол орнатылған қолданба сертификатымен сәйкес келуі керек. Осыдан кейін Android өзінің орнату диалогын көрсетеді. Бірінші рет ол қолданбаға файлдарды орнатуға рұқсат беруді сұрайды.

`latest.json` ішіндегі файлдар сол репозиторийдің `v<нұсқа>` релизінде жатуы керек, басқа мекенжайлардан қолданбалар жүктемейді. Тексеруден өтпеген файл жойылады, ал қолданба жаңа нұсқаны қолмен жүктеуді ұсынады. Жаңарту кезінде үлгерім мен баптаулар сақталады.

Ашық кілтсіз Windows (бос `pubkey`) жаңартуларды іздемейді және карточканы көрсетпейді. Android жаңарту кілтін қолданбайды: APK түпнұсқалығын қол қою сертификаты бойынша тексереді. Сондықтан екі кілтті де сақтау керек: жаңарту кілтімен Windows орнатқышына қол қойылады, APK кілтімен Android үшін әр жаңа нұсқаға қол қойылады. Автоматты жаңарту пайда болғанға дейін шыққан нұсқалар және кілтсіз құрастырылған Windows орнатқыштары өздігінен жаңармайды: оларға жаңа нұсқаны бір рет қолмен орнату керек.

### Жаңарту кілті

Бір рет жасалады, `apps/desktop` ішінен:

```bash
npx tauri signer generate -w ~/.tauri/exam-trainer.key
```

Пәрмен құпиясөз сұрап, екі файл жазады: жабық кілт `exam-trainer.key` және ашық кілт `exam-trainer.key.pub`. `.pub` ішіндегі жолды `tauri.conf.json` ішіндегі `plugins.updater.pubkey` өрісіне қойып, коммит жасаңыз. Жабық кілтті репозиторийден тыс ұстаңыз (git `*.key` файлдарын көрмейді) және оның көшірмесін құпиясөзбен бірге сақтаңыз. Ол жоғалса, бұрынғы ашық кілті бар қолданбалар жаңа нұсқаларды қабылдамайды.

## Windows орнатқышына қол қою (SignPath)

Кодқа қол қойылмаған орнатқышты Windows SmartScreen «Белгісіз жариялаушы» ескертуімен қарсы алады. Ашық жобалар [SignPath Foundation](https://signpath.org) арқылы тегін қол қоя алады, бірақ онда тек GitHub Actions жоба репозиторийінен құрастырған нәрсеге қол қойылады. Сондықтан релиздік орнатқышты [`.github/workflows/release.yml`](../.github/workflows/release.yml) workflow-сы құрастырады. APK кілті мен жаңарту кілті GitHub-қа түспейді: APK және `latest.json` бұрынғыдай сіздің компьютеріңізде дайындалады.

Workflow `vX.Y.Z` тегімен немесе қолмен іске қосылады (Actions, Windows installer, Run workflow). Ол банктерді сол иесінің `exam-content` репозиторийінен алады (репозиторий жария болуы керек), кодты және банктерді тексереді, қолданбаны құрастырады және `exam-desktop.exe` файлын қол қоюға жібереді. Содан кейін қол қойылған қолданбаны орнатқышқа орайды және орнатқышты қол қоюға жібереді. Екі қолтаңбаның әрқайсысын SignPath-та өзіңіз растайсыз, workflow растауды екі сағатқа дейін күтеді. Дайын орнатқыш іске қосу бетіндегі `windows-installer-<нұсқа>` артефактінде 14 күн сақталады. SignPath бапталмайынша, workflow сол нәрселерді құрастырады, тексереді және сынап орнатады, тек қол қоймайды. Осы коммитте `plugins.updater.pubkey` бос болса, іске қосу тоқтайды: мұндай орнатқыш ешқашан өзі жаңармайды.

Баптау, бір рет:

1. [signpath.org](https://signpath.org) сайтында өтінім беріңіз. Олардың шарттары: ашық лицензия (GPL жарайды), жабық код жоқ, барлық қатысушыларда GitHub-та және SignPath-та екі факторлы кіру, ал жоба қол қойылатын күйінде бұрыннан шығарылған. Сондықтан бірінші релиз қолтаңбасыз шығады. SignPath талап ететін «Кодқа қол қою саясаты» бөлімі README-де бар.
2. Мақұлданғаннан кейін SignPath ұсынатын баптауды өтіңіз (ұйым, жоба, қол қою саясаты, GitHub Actions-ты құрастыру көзі ретінде қосу). Репозиторий жобада `application` және `installer` слагтары бар екі артефакт конфигурациясын күтеді: оларды жасап, оларға [`.signpath/artifact-configurations/`](../.signpath/artifact-configurations/) ішіндегі файлдарды қойыңыз.
3. GitHub репозиторийінде (Settings, Secrets and variables, Actions) `SIGNPATH_ORGANIZATION_ID`, `SIGNPATH_PROJECT` (жоба слагы) және `SIGNPATH_POLICY` (`release-signing`; сынақ сертификатымен байқау үшін `test-signing`) айнымалыларын және `SIGNPATH_API_TOKEN` құпиясын беріңіз.
4. Үш README-дің «Кодқа қол қою саясаты» бөліміне SignPath талап ететін жолды қосыңыз: "Free code signing provided by [SignPath.io](https://about.signpath.io), certificate by [SignPath Foundation](https://signpath.org)".

`release-signing` саясатымен workflow тек SignPath Foundation-ның жарамды қолтаңбасы бар файлдарды қабылдайды (`test-signing` кезінде кез келген қолтаңбаны: тест сертификатына Windows сенбейді), ал қол қойылғаннан кейін орнатқышты бос қалтаға орнатып, орнатылған қолданбаның қолтаңбасын тексереді. NSIS қолданбаның жанына салатын жою бағдарламасына жеке қолтаңба қойылмайды.

## Релизді шығару

1. `apps/desktop/src-tauri/tauri.conf.json` ішіндегі `version` мәнін көтеріңіз (тек `0.2.0` түрінде). Орнатқыш атауындағы нөмір және APK нұсқасы содан алынады.
2. Қол қойылған APK файлын (`npx tauri android build --apk --target aarch64`, қол қою README-де сипатталған) құрастырыңыз. Орнатқышты GitHub Actions-тан алыңыз: тег жіберіңіз (`git tag v0.2.0`, `git push origin v0.2.0`) немесе workflow-ны қолмен іске қосыңыз, SignPath-та екі қолтаңбаны растап, `windows-installer-0.2.0` артефактін жүктеп алыңыз. Бұл zip мұрағаты, ішінде `exam-trainer-windows-setup.exe` бар. SignPath-сыз орнатқышты өзіңіз де құрастыра аласыз: `apps/desktop` ішінде `npx tauri build`. Келесі қадамдағы скрипт APK немесе орнатқыш ескі нұсқа болса, жұмыс істеуден бас тартады.
3. Жабық жаңарту кілтін беріп, репозиторий түбірінен `npm run release` іске қосыңыз. `--windows` GitHub Actions-тағы орнатқышқа сілтейді; бұл параметрсіз скрипт жергілікті құрастырманың орнатқышын алады:

   ```bash
   export TAURI_SIGNING_PRIVATE_KEY_PATH="$HOME/.tauri/exam-trainer.key"
   export TAURI_SIGNING_PRIVATE_KEY_PASSWORD="<құпиясөз>"
   npm run release -- --windows="$HOME/Downloads/exam-trainer-windows-setup.exe"
   ```

   PowerShell-де айнымалылар былай беріледі: `$env:TAURI_SIGNING_PRIVATE_KEY_PATH = "$HOME\.tauri\exam-trainer.key"`.

   Скрипт `release/` қалтасына (git оны көрмейді) орнатқыш пен APK файлын `exam-trainer-windows-setup.exe` және `exam-trainer-android.apk` атауларымен салады, екеуіне де жаңарту кілтімен қол қояды және `latest.json` жазады. Бұл қолтаңба SignPath қол қойып қойған файлға қойылады, сондықтан алдымен SignPath, содан кейін `npm run release`. Скрипт басқа нұсқадағы орнатқышты, орнатқыштың орнына қолданбаның өзін және кодқа жарамды қолтаңбасы жоқ орнатқышты қабылдамайды. SignPath жобаны мақұлдағанша `--unsigned` қосыңыз: сонда қолтаңбасыз орнатқыш ескертумен өтеді. `--notes="..."` `latest.json` файлына сипаттама қосады.
4. Релизді скрипт басып шығарған пәрменмен немесе GitHub-та қолмен (Releases, Draft a new release) сол үш файлмен жариялаңыз:

   ```bash
   gh release create v0.2.0 release/exam-trainer-windows-setup.exe release/exam-trainer-android.apk release/latest.json --title v0.2.0 --notes "Code signing policy: https://github.com/<пайдаланушы>/<код-репозиторийі>/blob/main/README.en.md#code-signing-policy"
   ```

   SignPath кодқа қол қою саясатына сілтемені әр релиз бетінде талап етеді.

Тег дәл `v` және `tauri.conf.json` ішіндегі нұсқа болуы керек: `latest.json` осы тегтің файлдарына сілтейді. `latest` соңғы жарияланған релизге апарады, қараламаларды (draft) және алдын ала релиздерді (pre-release) өткізіп жібереді, сондықтан қолданбалар жаңа нұсқаны тек жарияланғаннан кейін көреді. Релизде әрқашан екі файл да болады: веб-нұсқа `latest` арқылы орнатқышқа да, APK файлына да сілтейді. Веб-нұсқаны қайта құрастырудың қажеті жоқ.
