# `exambank/2` мазмұн форматы

Формат пен қалталар орналасуының жалғыз сипаттамасы. Ережелердің машиналық нұсқасы JSON Schema түрінде беріледі, оны `schema` пәрмені жазады (құжаттың соңын қараңыз). Барлық мысалдар `examples/demo-content` ішінен алынған: бұл тексеру мен көрсетуге арналған бейтарап жиын.

Жібермес бұрын тексеріңіз, код репозиторийінің түбірінен:

```bash
node packages/content-tools/src/cli.ts validate <мазмұн-қалтасы>
```

Пәрмен құрылымды, схемаларды, жауап кілттерін және еркін жазуды тексереді: `accept` ішіндегі әрбір тұжырым дұрыс деп есептелуі тиіс, ал әрбір қате жауап нұсқасы мен `reject` ішіндегі әрбір жазба есептелмеуі тиіс. Қате болса, оларды тізім етіп шығарып, 1 кодымен аяқталады. Сәтті болса, `OK: 5 banks, 33 questions` деп жазады (сандар өзіңіздікі болады).

## Қалталардың орналасуы

Мазмұн түбірі дегеніміз `catalog.json` жатқан қалта. Қалған ағаш оқу бағдарламасының иерархиясын қайталайды:

```
catalog.json                                  түйін түрлері және «орын» белгісі
demo/                                         университет (node.json)
  science/                                    факультет
    bachelor/                                 дәреже
      applied-mathematics/                    мамандық
        year-1/                               курс
          semester-1/                         семестр
            node.json
            geography/                        банк (bank.json)
              bank.json
              questions/t01.json              тақырыптар бойынша сұрақтар
              translations/ru/t01.json        бөлек файлдардағы аудармалар
            natural-sciences/                 пән-топ (node.json)
              node.json
              physics/bank.json               деңгей банкі
              chemistry/bank.json
```

`validate` тексеретін ережелер:

- `node.json` бар қалта ағаштың түйіні болады. `bank.json` бар қалта сұрақтар банкі (бұдан әрі банк) болады және өзі жатқан қалтаның түйініне тиесілі. Қалта бір мезгілде екеуі бола алмайды.
- Екі файлы да жоқ, бірақ ішінде JSON бар немесе төменде түйіндер мен банктер жатқан қалта қате болып есептеледі: оның мазмұны үнсіз еленбей қалар еді.
- Банк мазмұн түбірінде тұра алмайды, ал банк қалтасының ішінде түйіндер мен басқа банктер болуы мүмкін емес.
- Ішінде еншілес түйіні де, банкі де жоқ түйін қате болып есептеледі.
- Түбірдегі `schema` және `source` қалталары, аты нүктеден басталатын қалталар (`.github`), сондай-ақ кез келген тереңдіктегі `questions`, `translations` және `node_modules` ағаштың бөлігі болып саналмайды. `questions` немесе `translations` ішінде банк қалтасынан тыс JSON жатса, бұл қате.
- Ағаштың тереңдігі мен түрлер құрамы еркін: `validate` тек әрбір түйіннің `kind` мәні `catalog.json` ішінде сипатталуын талап етеді. Жоғарыдағы мысал (жеті деңгей) деректермен беріледі.

Түйіндер мен банктер қалталарының аттары түйін идентификаторының және бет мекенжайының құрамына кіреді, сондықтан `validate` тек латын әріптерін, цифрларды, дефисті, астыңғы сызықты және нүктені қабылдайды (бірінші таңба әріп немесе цифр болуы керек). Банк идентификаторындағыдай кіші латын әріптерін, цифрларды және дефисті қолданыңыз.

## Идентификаторлар

| Не | Идентификатор | Өзгере ме |
| --- | --- | --- |
| Түйін | мазмұн түбірінен `/` арқылы жазылған қалта жолы, мысалы `demo/science/bachelor/earth-sciences/year-1/semester-1` | Қалтаның атын өзгерту немесе оны жылжыту идентификаторды өзгертеді. Студент осындай түйінде сақтаған таңдау тазаланады, үлгерімге зиян келмейді |
| Банк | `bank.json` ішіндегі `id` өрісі, мысалы `demo/geography` | Ешқашан өзгермейді |

Банк идентификаторы қалта жолына байланысты емес. Банкті түйіндер арасында жылжытуға және оның қалтасының атын өзгертуге болады: студенттердің үлгерім журналы банктің `id` мәніне сілтейді, ал `id` бұрынғыдай болса, үлгерім орнында қалады. Рұқсат етілген түрі: `^[a-z0-9-]+(/[a-z0-9-]+)*$`. `validate` банк `id` мәнінің қайталануын және түйін `id` мәнімен сәйкес келетін банк `id` мәнін қабылдамайды.

Банк тек бір қалтада жатады: екі банкте бірдей `id` болса, бұл қате. Бір пән екі семестрде оқытылса, екі бөлек банк жасаңыз.

## `catalog.json`

Түйін түрлерін сипаттайды. Түрлердің атаулары тізімдерде түйін атының астында көрсетіледі.

```json
{
  "format": "exambank/2",
  "kinds": {
    "university": { "title": { "ru": "Университет", "kk": "Университет", "en": "University" } },
    "semester": { "title": { "ru": "Семестр", "kk": "Семестр", "en": "Semester" }, "place": true },
    "subject": { "title": { "ru": "Предмет", "kk": "Пән", "en": "Subject" } }
  }
}
```

`place: true` қолданба студенттің орны деп санайтын түрді белгілейді. Әдетте бұл семестр: студент «университет, факультет, дәреже, мамандық, курс, оқу жылы, семестр» тізбегін бір рет таңдайды. Деңгейлерді деректер белгілейді: мысалы, курс пен семестрдің арасына «оқу жылы» түйінін қоюға болады, сонда 2025 және 2026 жылдардағы 1-курс бөлек сақталады. Қолданба орын қалтасын есте сақтап, іске қосқанда соны ашады. Жолдағы бірде-бір түрде белгі болмаса, орын болып банктер жатқан бірінші қалта саналады. Орыннан жоғары тұрған қалталар таңдау қадамдары, одан төмендегілері пәндер. `place` өрісінен басқа түрдің жалғыз өрісі: `title`.

Жаңа деңгей қосу үшін, мысалы «кафедра», түрді `catalog.json` ішінде сипаттап, қажетті `kind` мәні бар `node.json` файлы жатқан қалта жасаңыз.

## Түйін: `node.json`

```json
{
  "kind": "semester",
  "title": { "en": "Semester 1", "ru": "1 семестр" },
  "order": 10,
  "items": ["geography", "natural-sciences"]
}
```

| Өріс | Міндетті | Мағынасы |
| --- | --- | --- |
| `kind` | иә | `catalog.json` ішіндегі түр |
| `title` | иә | Атауы: жол немесе аудармалар жиыны (төменде қараңыз) |
| `order` | жоқ | `items` ішінде жоқ көрші түйіндер арасында сұрыптауға арналған сан. Кішісі жоғары тұрады; тең болса, қалта аты шешеді. Түбірлік түйіндер де осылай сұрыпталады |
| `items` | жоқ | Ішкі түйіндер мен банктер қалталарының көрсету ретімен жазылған аттары. Тізімделгендері бірінші тұрады және түйіндер мен банктерді араластыра алады; қалғаны олардан кейін келеді |

`node.json` ішіндегі кез келген басқа өріс қате болып саналады. `items` ішіндегі ат бар ішкі қалтаны атауы және қайталанбауы тиіс.

Түйін ішіндегі көрсету реті былай құралады: алдымен `items` ішіндегі қалталар, одан кейін тізімделмеген түйіндер (`order` бойынша, содан кейін аты бойынша), одан кейін тізімделмеген банктер (аты бойынша; банктердің өз `order` өрісі жоқ). Жоғарыдағы мысалда `geography` банкі `natural-sciences` түйінінен бұрын тек екеуі де `items` ішінде аталғандықтан тұр.

Екі `order` өрісін шатастырмаңыз. `node.json` ішінде бұл сұрыптауға арналған сан. Түйіннің құрастырылған манифестінде `order` ішкі түйіндер мен банктердің көрсету ретімен жазылған идентификаторларының дайын тізімі; оны `compile` құрады, қолмен жазылмайды.

### Пән-топ

Ішінде банктері бар `subject` түріндегі түйін бір пәнді бірнеше деңгей банктерінен құрайды. Демода бұл `natural-sciences`:

```json
{
  "kind": "subject",
  "title": { "en": "Natural sciences", "ru": "Естественные науки" },
  "order": 10,
  "items": ["physics", "chemistry"]
}
```

Ішінде `physics/` және `chemistry/` қалталары жатыр, әрқайсысының өз `bank.json` файлы бар.

### Қолданба ағаштан қалай өтеді

- Бір ғана жазбасы бар қалта (бір ішкі түйін немесе бір банк) өткізіліп жіберіледі: қолданба екі немесе одан көп жазбадан таңдау кездескенше әрі қарай жүре береді. Мұндай қадамдардың бәрі бір өтуде орындалады. Жалғыз жазба банк болса, сол банк ашылады.
- Қолданба таңдалған орынды құрылғыда есте сақтайды. Есте сақталған қалта мазмұнда енді жоқ болса, студент қайта таңдайды.
- Студент таңдауды «Ауыстыру» түймесімен өзгертеді, ал Баптауларда тазалайды.

## Бірнеше тілдегі мәтін

Кез келген мәтін өрісі екі түрдің бірін қабылдайды:

```json
"question": "Банк тіліндегі мәтін"
"question": { "en": "Text", "ru": "Текст" }
```

Банкте жол `language` өрісіндегі тілді білдіреді. `node.json` ішінде қолданба жолды кез келген тілде болса да, сол күйінде көрсетеді. Аударуды біртіндеп жүргізуге болады: қажетті тіл болмаса, қолданба түпнұсқа тіліндегі мәтінді көрсетеді. Сұрақ нөмірі барлық аудармаға ортақ, сондықтан үлгерім тілге байланысты емес.

Қолданба тұжырымдарды, жауап нұсқаларын және түсіндірмелерді KaTeX формулалары бар Markdown ретінде көрсетеді (жол ішінде `$x^2$`, бөлек блок ретінде `$$…$$`). Шикі HTML мен сілтемелер өшірілген.

## Банк: `bank.json`

```json
{
  "format": "exambank/2",
  "id": "demo/geography",
  "subject": { "en": "Geography", "ru": "География" },
  "language": "en",
  "translations": { "ru": "machine" },
  "license": "CC0-1.0",
  "authors": ["Demo Authors"],
  "difficulty_scale": [
    { "level": 1, "title": { "en": "Recall", "ru": "Знание" } },
    { "level": 2, "title": { "en": "Understanding", "ru": "Понимание" } }
  ],
  "scoring": { "multiple_choice": "exact" },
  "topics": [
    { "id": 1, "name": { "en": "Continents and oceans", "ru": "Континенты и океаны" } },
    { "id": 2, "name": { "en": "Rivers and mountains", "ru": "Реки и горы" } }
  ]
}
```

| Өріс | Міндетті | Мағынасы |
| --- | --- | --- |
| `format` | иә | Әрқашан `exambank/2` |
| `id` | иә | Банк идентификаторы (жоғарыда қараңыз) |
| `subject` | иә | Пәннің атауы |
| `language` | иә | Түпнұсқа тілі: жол өрістері осы тілде жазылған |
| `translations` | жоқ | Тілдер бойынша аударма сапасы: `machine` немесе `reviewed`. Жаңа тілдерге `merge-translations` пәрмені `machine` қояды, ал `reviewed` мәнін қолмен қоясыз |
| `difficulty_scale` | жоқ | Сұрақтардың `difficulty_level` өрісіне арналған шкала. Деңгей саны кез келген болуы мүмкін, шкала болмауы да мүмкін |
| `scoring.multiple_choice` | иә | `exact`: тек толық жиын есептеледі. `partial`: ішінара балл |
| `topics` | иә | Кемінде бір тақырып. Тақырыптың `id` мәні сұрақтарда `topic_id` ретінде қолданылады |
| `created_on`, `license`, `authors` | жоқ | Банк туралы мәліметтер |
| `exam` | жоқ | Емтихан профилі бар еркін нысан. Қолданба оны қазір оқымайды |
| `sources`, `source_catalog`, `source_indexing`, `notes`, `legacy` | жоқ | Банктің шығу тегі туралы қызметтік мәліметтер |

Тақырыптар қосымша өрістерге рұқсат береді. Қалған бөлігінде схема қатаң: өріс атындағы қате жазу қатеге әкеледі.

## Сұрақ файлдары

Сұрақтар `<банк>/questions/*.json` ішінде жатады, әр тақырыпқа бір файл. Файл аты кез келген болады (`t01.json` қалыптасқан), тақырыпты сұрақтың `topic_id` өрісі белгілейді. Бір файлда 15-тен 50-ге дейін сұрақ ұстаған ыңғайлы. Жаңа тақырып үшін `topics` ішіне жазба қосып, жаңа файл жасаңыз.

```json
{
  "format": "exambank/2",
  "bank": "demo/geography",
  "questions": [ … ]
}
```

`bank` өрісі банктің `id` мәніне сәйкес келуі тиіс.

### Сұрақтың жалпы өрістері

| Өріс | Міндетті | Мағынасы |
| --- | --- | --- |
| `id` | иә | Оң бүтін сан, банк ішінде бірегей. Өзгермейді және қайта қолданылмайды: үлгерім оған сілтейді |
| `topic_id` | иә | `bank.json` ішіндегі тақырыптың `id` мәні |
| `type` | иә | `single_choice`, `multiple_choice`, `short_text`, `numeric`, `open` |
| `question` | иә | Сұрақтың тұжырымы |
| `difficulty_level` | жоқ | Банк шкаласы бойынша пәндік күрделілік. Студенттің жауапты таңдайтынына немесе теріп жазатынына байланысты емес |
| `exam_block` | жоқ | Емтихан блогының белгісі. Ядродағы сессия блоктар бойынша іріктей алады; банк экраны мұндай сүзгіні көрсетпейді |
| `explanation` | жоқ | Жауаптан кейін көрсетілетін түсіндірме |
| `source_references` | жоқ | Кілтті тексеру үшін дереккөзге қызметтік сілтемелер |
| `retired` | жоқ | Көрсетуден алынған сұрақта `true`. Сұрақты жоюға болмайды |

Басқа өрістер болмауы тиіс.

### Жауап таңдау: `single_choice` және `multiple_choice`

```json
{
  "id": 1,
  "topic_id": 1,
  "difficulty_level": 1,
  "type": "single_choice",
  "question": { "en": "The largest ocean on Earth is the...", "ru": "Самый большой океан на Земле называется..." },
  "options": [
    { "id": "A", "text": { "en": "Atlantic Ocean", "ru": "Атлантический океан" } },
    { "id": "B", "text": { "en": "Pacific Ocean", "ru": "Тихий океан" } }
  ],
  "correct_answers": ["B"],
  "free_input": {
    "answers": [
      { "for": "B", "accept": { "en": ["Pacific", "Pacific Ocean"], "ru": ["Тихий", "Тихий океан"] } }
    ]
  },
  "explanation": "The Pacific Ocean covers about a third of the planet's surface."
}
```

(Демода бұл сұрақтың бес жауап нұсқасы бар; мұнда қысқартылған.) Ережелер: кемінде екі жауап нұсқасы болады; нұсқалардың `id` мәндері бірегей; `single_choice` үшін `correct_answers` ішінде дәл бір нұсқа, `multiple_choice` үшін бір немесе одан көп нұсқа тұрады; әрбір дұрыс жауап нұсқалар арасында бар. Жауап нұсқаларының ретін қолданба өзі араластырады.

### Еркін жазу: `free_input` блогы

Блок сол сұрақты «Жазу» режимінің тапсырмасына айналдырады: жауап нұсқалары жасырылады, студент жауапты теріп жазады. Блок міндетті емес. Онсыз сұрақ жазу режимінде өзін-өзі тексеру ретінде беріледі (студент дұрыс жауапты көріп, оны білген-білмегенін өзі белгілейді) немесе Баптауларда көрсетілгеніндей өткізіліп жіберіледі.

| Өріс | Мағынасы |
| --- | --- |
| `answers` | Әрбір дұрыс жауап нұсқасына бір жазба: `for` (нұсқаның әрпі) және `accept` (тілдер бойынша есептелетін тұжырымдар). Дәл `correct_answers` жиынын қамтуы тиіс |
| `question` | Жазу режиміне арналған басқа тұжырым. Түпнұсқа жауап нұсқаларына сүйенсе немесе оларсыз түсініксіз болса қажет (демода Оңтүстік жарты шардағы материктер туралы сұрақ осылай жасалған, мысал төменде) |
| `reject` | Жақын, бірақ қате жауаптар, олар жауап нұсқаларының арасында жоқ |
| `typos` | `"off"` осы сұрақта қате жазуға тыйым салады; әдепкісі `"auto"` |
| `answers[].ordered` | Жауаптағы сөздер реті маңызды болса, `true` |

Блокты жауапты нұсқаның көмегінсіз де атауға болатын жағдайда ғана қосыңыз: термин, есім, сан, қысқа тіркес. Ұзын тұжырымды блоксыз қалдырыңыз.

`accept` ішіне нені жазу керек: негізгі форманы (атау септік, жекеше түр), жалпы қабылданған синонимдер мен қысқартуларды, көлем нұсқаларын (`Pacific` және `Pacific Ocean`).

Нені жазудың қажеті жоқ: регистрді, бос орындарды, тыныс белгілерін, `ё` әрпін, септік жалғауларын, сұрақтың өзіндегі сөздерді, қате жазуларды. Мұның бәрін тексеру өзі ескереді. Қате жазулар төрт таңбадан ұзын сөздерде кешіріледі: сегіз таңбаға дейін бір қате, ұзынырақ сөздерде екі қате. Сандар мен қысқа сөздер қатаң тексеріледі. `ә ғ қ ң ө ұ ү һ і` әріптерін ең жақын қарапайым әріптермен (`а г к н о у у х и`) ауыстыруға болады: орыс пернетақтасымен теріп жазғанда дәл осылай шығады, және мұндай жауап есептеледі.

Тексеру синонимдерді болжамайды. Тек тізімделгені есептеледі, ал банктің басқа терминіне немесе қате жауап нұсқасына ұқсас жауап қабылданбайды. Барлық тілдердің тұжырымдары бір тізім ретінде тексеріледі: `en` үшін жазылған синоним орыс интерфейсінде де есептеледі. Синонимдер жиынын тілдер бойынша параллель ұстаңыз.

Бірнеше жауабы бар сұрақ `answers` ішіндегі жазбалар санындай енгізу өрісін береді. Жауаптар реті маңызды емес:

```json
"free_input": {
  "question": { "en": "Name the two continents that lie entirely in the Southern Hemisphere.", "ru": "Назовите два материка, которые целиком расположены в Южном полушарии." },
  "answers": [
    { "for": "A", "accept": { "en": ["Antarctica"], "ru": ["Антарктида"] } },
    { "for": "B", "accept": { "en": ["Australia"], "ru": ["Австралия"] } }
  ]
}
```

### Тек жазу: `short_text`

Жауап нұсқалары жоқ сұрақ. `answers`, `reject`, `typos` өрістері тікелей сұрақтың ішінде тұрады, `for` қажет емес.

```json
{
  "id": 5,
  "topic_id": 1,
  "type": "short_text",
  "question": "What is the result of a multiplication called?",
  "answers": [ { "accept": { "en": ["product", "the product"] } } ],
  "reject": { "en": ["factor", "sum"] },
  "typos": "off",
  "explanation": "In 6 x 7 = 42 the numbers 6 and 7 are factors and 42 is the product."
}
```

### Сан: `numeric`

```json
{
  "id": 3,
  "topic_id": 1,
  "type": "numeric",
  "question": "What is 15% of 200?",
  "answer": { "value": 30, "tolerance": 0, "unit": null }
}
```

`tolerance` екі бағытта да рұқсат етілген ауытқуды береді (әдепкісі 0). `unit` міндетті емес: жол, аудармалар жиыны немесе `null`. Ондық бөлшектегі үтір мен нүкте бірдей саналады. `numeric` сұрағы тек жазу режимінде болады.

### Толық жауап: `open`

Студент өз жауабын үлгімен салыстырып, өзі тексереді. Жауап режимі тек өзін-өзі тексеру.

```json
{
  "id": 7,
  "topic_id": 1,
  "type": "open",
  "question": "Explain why the sum of two odd numbers is always even.",
  "model_answer": "Write the odd numbers as 2a + 1 and 2b + 1. Their sum is 2a + 2b + 2 = 2(a + b + 1), which has the factor 2, so it is even.",
  "rubric": [
    { "points": 1, "criterion": "Writes odd numbers in the form 2k + 1" },
    { "points": 1, "criterion": "Shows that the sum has the factor 2" }
  ]
}
```

`rubric` міндетті емес; `points` оң сан болады.

## Аудармалар бөлек файлдармен

Аудармашы банктің бастапқы файлдарын түзетпейді. Ол қасына аударма файлдарын (сайдкарларды) салады, ал пәрмен оларды банкке біріктіреді:

```
<банк>/translations/<локаль>/bank.json         пән және күрделілік деңгейлерінің атаулары
<банк>/translations/<локаль>/<тақырып>.json    бір тақырып: атауы, сұрақтар, жауап нұсқалары
```

Тақырып мысалы (`geography/translations/ru/t01.json`):

```json
{
  "bank": "demo/geography",
  "locale": "ru",
  "topic_id": 1,
  "topic_name": "Континенты и океаны",
  "questions": {
    "1": {
      "question": "Самый большой океан на Земле называется...",
      "options": { "A": "Атлантический океан", "B": "Тихий океан" },
      "free_input": { "accept": { "B": ["Тихий", "Тихий океан"] } }
    },
    "5": { "question": "Сколько материков в распространённой модели из семи материков?" }
  }
}
```

(Демода 1-сұрақтың бес жауап нұсқасы бар; мұнда қысқартылған.) Банктің сайдкары: `{ "bank": "demo/geography", "locale": "ru", "subject": "География", "difficulty_scale": { "1": "Знание", "2": "Понимание" } }`.

Сайдкарлар нені аударады: пәннің атауын, деңгейлердің атауларын, тақырыптардың атауларын, сұрақ мәтінін, жауап нұсқаларын, ал таңдау сұрақтарында тағы `free_input` (`question`, жауап нұсқаларының әріптері бойынша `accept`, `reject`). Жауап нұсқалары жоқ сұрақтардың сайдкарында тек `question` болады. Түсіндірмелер, `short_text.answers`, `model_answer` және `rubric` сайдкармен аударылмайды: аудармалар жиынын тікелей сұраққа қосыңыз.

Біріктіру:

```bash
node packages/content-tools/src/cli.ts merge-translations <мазмұн-қалтасы>
```

Пәрмен жолдарды `{ "en": "түпнұсқа", "ru": "аударма" }` сияқты жиындарға айналдырады, ал дайын жиындарда тек тіл кілтін қояды немесе ауыстырады. Түпнұсқа өзгермейді. Жаңа тіл үшін `bank.json` ішінде, егер онда `reviewed` тұрмаса, `"translations": { "ru": "machine" }` пайда болады. Қайта іске қосу ештеңені өзгертпейді.

Пәрмен алдымен барлық сайдкарларды тексереді, содан кейін ғана бір нәрсе жазады. Қателер (шығу коды 1, ештеңе жазылмайды): сұрақ осы банктен немесе осы тақырыптан емес, жауап нұсқасы жетіспейді немесе артық, бос жол, `bank` банктің `id` мәніне сәйкес келмейді, `locale` сайдкар қалтасына сәйкес келмейді, локаль банктің `language` мәнімен бірдей, жол `translations/<локаль>/<файл>.json` түрінде емес. Ескертулер (код 0, қалғаны біріктіріледі): тақырып сұрағының аудармасы жоқ, `free_input` үшін `accept` аудармасы жоқ. Сұрақта бастапқы `free_input.question` болмаса, аударылған тұжырым қосылмайды: ол түпнұсқаны жасырып тастар еді.

## 1.0 форматындағы банктер

1.0 форматындағы файл (әр банкке бір JSON) `migrate` пәрменімен түрлендіріледі, ол `bank.json` мен `questions/` қалтасын көрсетілген банк қалтасына жазады:

```bash
node packages/content-tools/src/cli.ts migrate <v1.json> <банк-id> <банк-қалтасы>
```

Содан кейін банк қалтасын ағашқа қолайлы түйіннің астына салу керек. 1.0 форматымен салыстырғанда не өзгерді: бір файл `bank.json` мен тақырып файлдарына бөлінген; `instruction` өрісі сұрақтардан алынып тасталған («Бір дұрыс нұсқаны таңдаңыз» жазуын қолданба өзі көрсетеді); есептегіштер (`question_count` және соған ұқсастар) сақталмайды, есептеледі; мәтіндер жол немесе аудармалар жиыны болуы мүмкін; `free_input`, `explanation`, `retired` және `short_text`, `numeric`, `open` типтері қосылған. `verify <v1.json> <банк-қалтасы>` пәрмені банкті қайтадан 1.0 форматына жинап, бастапқы файлмен салыстырады. Банкке мазмұнды түзетулер енгізгеннен кейін айырмашылықтың болуы күтіледі.

## Қолданба нені алады

`compile <мазмұн-қалтасы> <нәтиже-қалтасы>` пәрмені мазмұнды тексереді (қате болса, ештеңе жазбайды) және аттарында мазмұн хэші бар файлдарды жинайды: SHA-256 хэшінің алғашқы 16 таңбасы.

```
index.json              версия, түйін түрлері, түбірлік түйіндер (атында хэші жоқ жалғыз файл)
nodes/<хэш>.json        түйін манифесті: id, kind, title, children, banks, order
banks/<хэш>.json        банк және оның барлық сұрақтары
```

Нәтиже қалтасы жинау алдында тазаланады, сондықтан ол мазмұн қалтасының ішінде жатпауы, оны қамтымауы және онымен сәйкес келмеуі тиіс. Ол тек бос қалтаны немесе алдыңғы жинақты (ішінде тек `nodes`, `banks`, `index.json`) өшіреді; кез келген басқа қалта болса, пәрмен ештеңе өшірмей тоқтайды. Қолданба `index.json` файлын қайта оқиды, манифесттер мен банктерді хэш бойынша жүктейді, әр файлдың хэшін тексереді және оны мәңгілікке кэштейді. Алынған сұрақтар (`retired`) банк файлында қалады, бірақ есептегіштерге кірмейді. Олардың `id` мәндері түйін манифесіндегі банк жазбасында өсу ретімен тізіледі (`retired` өрісі, алынған сұрағы жоқ банкте ол болмайды), сондықтан каталог оларды меңгерілген деп санамайды.

Редактор немесе генератор үшін JSON Schema: `node packages/content-tools/src/cli.ts schema <нәтиже-қалтасы>` пәрмені `bank.schema.json`, `questions.schema.json`, `node.schema.json` және `catalog.schema.json` файлдарын жазады.
