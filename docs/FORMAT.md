# Формат контента `exambank/2`

Единственное описание формата и раскладки папок. Машинная версия правил лежит в JSON Schema; её пишет команда `schema` (см. конец документа). Все примеры взяты из `examples/demo-content`: это нейтральный набор для проверки и демонстрации.

Проверка перед отправкой, из корня репозитория кода:

```bash
node packages/content-tools/src/cli.ts validate <папка-контента>
```

Команда проверяет структуру, схемы, ключи и свободный ввод: каждая формулировка из `accept` должна засчитываться, а каждый неверный вариант и каждая запись `reject` не должны. При ошибках она печатает их списком и завершается с кодом 1. При успехе пишет `OK: 5 banks, 33 questions` (числа свои).

## Раскладка папок

Корень контента это папка с `catalog.json`. Остальное дерево повторяет иерархию учебной программы:

```
catalog.json                                  виды узлов и отметка «место»
demo/                                         университет (node.json)
  science/                                    факультет
    bachelor/                                 степень
      applied-mathematics/                    специальность
        year-1/                               курс
          semester-1/                         семестр
            node.json
            geography/                        банк (bank.json)
              bank.json
              questions/t01.json              вопросы по темам
              translations/ru/t01.json        переводы отдельными файлами
            natural-sciences/                 предмет-группа (node.json)
              node.json
              physics/bank.json               банк-уровень
              chemistry/bank.json
```

Правила, которые проверяет `validate`:

- Папка с `node.json` это узел дерева. Папка с `bank.json` это банк, он принадлежит узлу, в папке которого лежит. Папка не может быть и тем и другим.
- Папка без обоих файлов, но с JSON внутри или с узлами и банками ниже, считается ошибкой: её содержимое было бы молча проигнорировано.
- Банк не может лежать в корне контента, а внутри папки банка не может быть узлов и других банков.
- Узел без дочерних узлов и без банков считается ошибкой.
- Папки `schema` и `source` в корне, папки, имя которых начинается с точки (`.github`), а также `questions`, `translations` и `node_modules` на любой глубине деревом не считаются. Если в `questions` или `translations` лежит JSON вне папки банка, это ошибка.
- Глубина дерева и состав видов произвольны: `validate` требует лишь, чтобы `kind` каждого узла был описан в `catalog.json`. Пример выше (семь уровней) задан данными.

Имена папок узлов и банков входят в идентификатор узла и в адрес страницы, поэтому `validate` принимает только латиницу, цифры, дефис, подчёркивание и точку (первый знак это буква или цифра). Берите строчную латиницу, цифры и дефис, как в идентификаторе банка.

## Идентификаторы

| Что | Идентификатор | Меняется ли |
| --- | --- | --- |
| Узел | путь папки от корня контента через `/`, например `demo/science/bachelor/earth-sciences/year-1/semester-1` | Переименование или перенос папки меняет его. Запомненный выбор студента на таком узле сбрасывается, прогресс не страдает |
| Банк | поле `id` в `bank.json`, например `demo/geography` | Не меняется никогда |

Идентификатор банка не зависит от пути папки. Банк можно переносить между узлами и переименовывать его папку: на `id` банка ссылается журнал прогресса студентов, и пока `id` прежний, прогресс остаётся на месте. Допустимый вид: `^[a-z0-9-]+(/[a-z0-9-]+)*$`. `validate` отклоняет повтор `id` банка и `id` банка, совпадающий с `id` узла.

Банк лежит ровно в одной папке: один и тот же `id` в двух банках считается ошибкой. Если один предмет читается в двух семестрах, заведите два разных банка.

## `catalog.json`

Описывает виды узлов. Заголовки видов показываются в списках под названием узла.

```json
{
  "format": "exambank/2",
  "kinds": {
    "university": { "title": { "ru": "Университет", "kk": "Университет", "en": "University" } },
    "semester": { "title": { "ru": "Семестр", "kk": "Семестр", "en": "Semester" }, "place": true },
    "subject": { "title": { "ru": "Предмет", "kk": "Пән", "en": "Subject" } }
  }
}
```

`place: true` отмечает вид, который приложение считает местом студента. Обычно это семестр: студент один раз выбирает цепочку «университет, факультет, степень, специальность, курс, учебный год, семестр». Уровни задаются данными: например, между курсом и семестром можно поставить узел «учебный год», чтобы курс 1 за 2025 и за 2026 год лежал отдельно. Приложение запоминает папку-место и при запуске открывает её. Если ни у одного вида на пути нет отметки, местом считается первая папка, в которой лежат банки. Папки выше места это шаги выбора, ниже места это предметы. Остальные поля вида: только `title`.

Чтобы добавить новый уровень, например «кафедра», опишите вид в `catalog.json` и создайте папку с `node.json` нужного `kind`.

## Узел: `node.json`

```json
{
  "kind": "semester",
  "title": { "en": "Semester 1", "ru": "1 семестр" },
  "order": 10,
  "items": ["geography", "natural-sciences"]
}
```

| Поле | Обязательно | Смысл |
| --- | --- | --- |
| `kind` | да | Вид из `catalog.json` |
| `title` | да | Название: строка или набор переводов (см. ниже) |
| `order` | нет | Число для сортировки среди соседних узлов, которых нет в `items`. Меньше значит выше; при равенстве решает имя папки. Корневые узлы сортируются так же |
| `items` | нет | Имена папок вложенных узлов и банков в порядке показа. Перечисленные идут первыми и могут смешивать узлы и банки; остальные следуют после них |

Любое другое поле в `node.json` считается ошибкой. Имя в `items` должно называть существующую вложенную папку и не повторяться.

Порядок показа внутри узла складывается так: сначала папки из `items`, затем неперечисленные узлы (по `order`, затем по имени), затем неперечисленные банки (по имени; у банков своего `order` нет). В примере выше банк `geography` стоит перед узлом `natural-sciences` только потому, что оба названы в `items`.

Не путайте два `order`. В `node.json` это число для сортировки. В скомпилированном манифесте узла `order` это готовый список идентификаторов вложенных узлов и банков в порядке показа; его строит `compile`, вручную его не пишут.

### Предмет-группа

Узел вида `subject` с банками внутри собирает предмет из нескольких банков-уровней. В демо это `natural-sciences`:

```json
{
  "kind": "subject",
  "title": { "en": "Natural sciences", "ru": "Естественные науки" },
  "order": 10,
  "items": ["physics", "chemistry"]
}
```

Внутри лежат папки `physics/` и `chemistry/`, у каждой свой `bank.json`.

### Как приложение проходит по дереву

- Папка с единственной записью (один дочерний узел или один банк) пропускается: приложение идёт дальше, пока не встретит выбор из двух и более записей. Все такие шаги выполняются за один переход. Если единственная запись это банк, открывается он.
- Приложение запоминает выбранное место на устройстве. Если запомненной папки в контенте больше нет, студент выбирает заново.
- Студент меняет выбор кнопкой «Сменить» и сбрасывает его в настройках.

## Текст на нескольких языках

Любое поле-текст принимает один из двух видов:

```json
"question": "Текст на языке банка"
"question": { "en": "Text", "ru": "Текст" }
```

В банке строка означает язык из поля `language`. В `node.json` приложение показывает строку как есть, на любом языке. Переводить можно постепенно: если нужного языка нет, приложение показывает текст на языке оригинала. Номер вопроса у всех переводов общий, поэтому прогресс не зависит от языка.

Формулировки, варианты и пояснения приложение показывает как Markdown с формулами KaTeX (`$x^2$` в строке, `$$…$$` отдельным блоком). Сырой HTML и ссылки отключены.

## Банк: `bank.json`

```json
{
  "format": "exambank/2",
  "id": "demo/geography",
  "subject": { "en": "Geography", "ru": "География" },
  "language": "en",
  "translations": { "ru": "machine" },
  "license": "CC0-1.0",
  "authors": ["Demo Authors"],
  "difficulty_scale": [
    { "level": 1, "title": { "en": "Recall", "ru": "Знание" } },
    { "level": 2, "title": { "en": "Understanding", "ru": "Понимание" } }
  ],
  "scoring": { "multiple_choice": "exact" },
  "topics": [
    { "id": 1, "name": { "en": "Continents and oceans", "ru": "Континенты и океаны" } },
    { "id": 2, "name": { "en": "Rivers and mountains", "ru": "Реки и горы" } }
  ]
}
```

| Поле | Обязательно | Смысл |
| --- | --- | --- |
| `format` | да | Всегда `exambank/2` |
| `id` | да | Идентификатор банка (см. выше) |
| `subject` | да | Название предмета |
| `language` | да | Язык оригинала: на нём написаны поля-строки |
| `translations` | нет | Качество перевода по языкам: `machine` или `reviewed`. Новые языки получают `machine` от `merge-translations`, `reviewed` ставят вручную |
| `difficulty_scale` | нет | Шкала для `difficulty_level` вопросов. Уровней может быть сколько угодно; шкалы может не быть |
| `scoring.multiple_choice` | да | `exact`: засчитывается только полный набор. `partial`: частичный балл |
| `topics` | да | Хотя бы одна тема. `id` темы используется в вопросах как `topic_id` |
| `created_on`, `license`, `authors` | нет | Сведения о банке |
| `exam` | нет | Свободный объект с профилем экзамена. Приложение читает два поля: `duration_minutes` (минуты) и `test_question_count` (число вопросов). Если оба заданы целыми положительными числами, в настройке пробного экзамена появляется кнопка «Как на экзамене». Остальные поля не читаются |
| `sources`, `source_catalog`, `source_indexing`, `notes`, `legacy` | нет | Служебные сведения о происхождении банка |

Темы допускают дополнительные поля. В остальном схема строгая: опечатка в имени поля приводит к ошибке.

## Файлы вопросов

Вопросы лежат в `<банк>/questions/*.json`, по одному файлу на тему. Имя файла любое (принято `t01.json`), тему задаёт `topic_id` вопроса. В файле удобно держать от 15 до 50 вопросов. Для новой темы добавьте запись в `topics` и новый файл.

```json
{
  "format": "exambank/2",
  "bank": "demo/geography",
  "questions": [ … ]
}
```

Поле `bank` должно совпадать с `id` банка.

### Общие поля вопроса

| Поле | Обязательно | Смысл |
| --- | --- | --- |
| `id` | да | Целое положительное число, уникальное в банке. Не меняется и не используется повторно: на него ссылается прогресс |
| `topic_id` | да | `id` темы из `bank.json` |
| `type` | да | `single_choice`, `multiple_choice`, `short_text`, `numeric`, `open` |
| `question` | да | Формулировка |
| `difficulty_level` | нет | Предметная сложность по шкале банка. С тем, выбирает студент ответ или вводит его, не связана |
| `exam_block` | нет | Метка блока экзамена. Сессия в ядре умеет отбирать по блокам; экран банка такого фильтра не показывает |
| `explanation` | нет | Пояснение после ответа |
| `source_references` | нет | Служебные ссылки на источник для проверки ключа |
| `retired` | нет | `true` у вопроса, снятого с показа. Удалять вопрос нельзя |

Других полей быть не должно.

### Выбор ответа: `single_choice` и `multiple_choice`

```json
{
  "id": 1,
  "topic_id": 1,
  "difficulty_level": 1,
  "type": "single_choice",
  "question": { "en": "The largest ocean on Earth is the...", "ru": "Самый большой океан на Земле называется..." },
  "options": [
    { "id": "A", "text": { "en": "Atlantic Ocean", "ru": "Атлантический океан" } },
    { "id": "B", "text": { "en": "Pacific Ocean", "ru": "Тихий океан" } }
  ],
  "correct_answers": ["B"],
  "free_input": {
    "answers": [
      { "for": "B", "accept": { "en": ["Pacific", "Pacific Ocean"], "ru": ["Тихий", "Тихий океан"] } }
    ]
  },
  "explanation": "The Pacific Ocean covers about a third of the planet's surface."
}
```

(В демо у вопроса пять вариантов; здесь сокращено.) Правила: не меньше двух вариантов; `id` вариантов уникальны; у `single_choice` в `correct_answers` ровно один вариант, у `multiple_choice` один или больше; каждый правильный ответ есть среди вариантов. Порядок вариантов приложение перемешивает само.

### Свободный ввод: блок `free_input`

Блок превращает тот же вопрос в задание режима «Ввод»: варианты скрыты, студент печатает ответ. Блок необязателен. Без него вопрос в режиме ввода идёт самопроверкой (студент видит правильный ответ и сам отмечает, знал ли его) или пропускается, как задано в настройках.

| Поле | Смысл |
| --- | --- |
| `answers` | По одной записи на каждый правильный вариант: `for` (буква варианта) и `accept` (засчитываемые формулировки по языкам). Должны покрывать ровно `correct_answers` |
| `question` | Другая формулировка для режима ввода. Нужна, если исходная опирается на варианты или без них неоднозначна (в демо так сделан вопрос про материки Южного полушария, пример ниже) |
| `reject` | Близкие, но неверные ответы, которых нет среди вариантов |
| `typos` | `"off"` запрещает опечатки в этом вопросе; по умолчанию `"auto"` |
| `answers[].ordered` | `true`, если порядок слов в ответе важен |

Добавляйте блок, только когда ответ можно назвать без подсказки: термин, имя, число, короткое словосочетание. Длинное утверждение оставьте без блока.

Что писать в `accept`: основную форму (именительный падеж, единственное число), общепринятые синонимы и сокращения, варианты объёма (`Pacific` и `Pacific Ocean`).

Что писать не нужно: регистр, пробелы, пунктуацию, `ё`, падежные окончания, слова из самой формулировки вопроса, опечатки. Это проверка учитывает сама. Опечатки прощаются в словах длиннее четырёх знаков: одна ошибка до восьми знаков, две в более длинных. Числа и короткие слова проверяются строго. Буквы `ә ғ қ ң ө ұ ү һ і` можно заменить ближайшими обычными (`а г к н о у у х и`): так выглядит набор на русской раскладке, и он засчитывается.

Проверка не угадывает синонимы. Засчитывается только перечисленное, а ответ, похожий на другой термин банка или на неверный вариант, отклоняется. Формулировки всех языков проверяются одним списком: синоним, записанный для `en`, засчитается и при русском интерфейсе. Держите наборы синонимов параллельными по языкам.

Вопрос с несколькими ответами даёт столько полей ввода, сколько записей в `answers`. Порядок ответов не важен:

```json
"free_input": {
  "question": { "en": "Name the two continents that lie entirely in the Southern Hemisphere.", "ru": "Назовите два материка, которые целиком расположены в Южном полушарии." },
  "answers": [
    { "for": "A", "accept": { "en": ["Antarctica"], "ru": ["Антарктида"] } },
    { "for": "B", "accept": { "en": ["Australia"], "ru": ["Австралия"] } }
  ]
}
```

### Только ввод: `short_text`

Вопрос без вариантов. Поля `answers`, `reject`, `typos` стоят прямо в вопросе, `for` не нужен.

```json
{
  "id": 5,
  "topic_id": 1,
  "type": "short_text",
  "question": "What is the result of a multiplication called?",
  "answers": [ { "accept": { "en": ["product", "the product"] } } ],
  "reject": { "en": ["factor", "sum"] },
  "typos": "off",
  "explanation": "In 6 x 7 = 42 the numbers 6 and 7 are factors and 42 is the product."
}
```

### Число: `numeric`

```json
{
  "id": 3,
  "topic_id": 1,
  "type": "numeric",
  "question": "What is 15% of 200?",
  "answer": { "value": 30, "tolerance": 0, "unit": null }
}
```

`tolerance` задаёт допустимое отклонение в обе стороны (по умолчанию 0). `unit` необязательна: строка, набор переводов или `null`. Запятая и точка в десятичной дроби равнозначны. Вопрос `numeric` бывает только в режиме ввода.

### Развёрнутый ответ: `open`

Студент проверяет себя сам по образцу. Режим ответа: только самопроверка.

```json
{
  "id": 7,
  "topic_id": 1,
  "type": "open",
  "question": "Explain why the sum of two odd numbers is always even.",
  "model_answer": "Write the odd numbers as 2a + 1 and 2b + 1. Their sum is 2a + 2b + 2 = 2(a + b + 1), which has the factor 2, so it is even.",
  "rubric": [
    { "points": 1, "criterion": "Writes odd numbers in the form 2k + 1" },
    { "points": 1, "criterion": "Shows that the sum has the factor 2" }
  ]
}
```

`rubric` необязателен; `points` это положительное число.

## Переводы отдельными файлами

Переводчик не правит исходные файлы банка. Он кладёт рядом файлы-переводы (сайдкары), а команда сливает их в банк:

```
<банк>/translations/<локаль>/bank.json     предмет и названия уровней сложности
<банк>/translations/<локаль>/<тема>.json   одна тема: название, вопросы, варианты
```

Пример темы (`geography/translations/ru/t01.json`):

```json
{
  "bank": "demo/geography",
  "locale": "ru",
  "topic_id": 1,
  "topic_name": "Континенты и океаны",
  "questions": {
    "1": {
      "question": "Самый большой океан на Земле называется...",
      "options": { "A": "Атлантический океан", "B": "Тихий океан" },
      "free_input": { "accept": { "B": ["Тихий", "Тихий океан"] } }
    },
    "5": { "question": "Сколько материков в распространённой модели из семи материков?" }
  }
}
```

(В демо у вопроса 1 пять вариантов; здесь сокращено.) Сайдкар банка: `{ "bank": "demo/geography", "locale": "ru", "subject": "География", "difficulty_scale": { "1": "Знание", "2": "Понимание" } }`.

Что переводится сайдкарами: название предмета, названия уровней, названия тем, текст вопроса, варианты, а у вопросов выбора ещё `free_input` (`question`, `accept` по буквам вариантов, `reject`). У вопросов без вариантов в сайдкаре только `question`. Пояснения, `short_text.answers`, `model_answer` и `rubric` сайдкарами не переводятся: добавьте набор переводов прямо в вопрос.

Слияние:

```bash
node packages/content-tools/src/cli.ts merge-translations <папка-контента>
```

Команда превращает строки в наборы `{ "en": "оригинал", "ru": "перевод" }`, а в готовых наборах задаёт или заменяет только ключ языка. Оригинал не меняется. В `bank.json` у нового языка появляется `"translations": { "ru": "machine" }`, если там не стоит `reviewed`. Повторный запуск ничего не меняет.

Сначала команда проверяет все сайдкары и только потом что-то записывает. Ошибки (код выхода 1, ничего не записано): вопрос не из этого банка или не из этой темы, не хватает варианта или он лишний, пустая строка, `bank` не совпадает с `id` банка, `locale` не совпадает с папкой сайдкара, локаль совпадает с `language` банка, путь не вида `translations/<локаль>/<файл>.json`. Предупреждения (код 0, остальное сливается): у вопроса темы нет перевода, у `free_input` нет перевода `accept`. Если у вопроса нет исходного `free_input.question`, переведённый не добавляется: он скрыл бы оригинал.

## Банки из формата 1.0

Файл версии 1.0 (один JSON на банк) переводится командой `migrate`, которая пишет `bank.json` и `questions/` в указанную папку банка:

```bash
node packages/content-tools/src/cli.ts migrate <v1.json> <id-банка> <папка-банка>
```

Папку банка нужно затем положить в дерево под подходящий узел. Что изменилось по сравнению с 1.0: один файл разложен на `bank.json` и файлы тем; поле `instruction` убрано из вопросов (подпись «Выберите один верный вариант» приложение показывает само); счётчики (`question_count` и подобные) не хранятся, а считаются; тексты могут быть строкой или набором переводов; добавлены `free_input`, `explanation`, `retired` и типы `short_text`, `numeric`, `open`. Команда `verify <v1.json> <папка-банка>` собирает банк обратно в формат 1.0 и сравнивает с исходным файлом. После содержательных правок банка расхождение ожидаемо.

## Что получает приложение

Команда `compile <папка-контента> <куда>` проверяет контент (при ошибках ничего не пишет) и собирает файлы, имена которых содержат хэш содержимого: первые 16 знаков SHA-256.

```
index.json              версия, виды узлов, корневые узлы (единственный файл без хэша в имени)
nodes/<хэш>.json        манифест узла: id, kind, title, children, banks, order
banks/<хэш>.json        банк и все его вопросы
```

Папка назначения стирается перед сборкой, поэтому она не должна лежать внутри папки контента, содержать её или совпадать с ней. Стирает она только пустую папку или прежнюю сборку (внутри лишь `nodes`, `banks`, `index.json`); с любой другой папкой команда остановится, ничего не удалив. Приложение перечитывает `index.json`, подгружает манифесты и банки по хэшу, проверяет хэш каждого файла и кэширует его навсегда. Снятые вопросы (`retired`) остаются в файле банка, но не входят в счётчики. Их `id` по возрастанию перечислены в записи банка в манифесте узла (поле `retired`, у банка без снятых вопросов его нет), чтобы каталог не засчитывал их как освоенные.

JSON Schema для редактора или генератора: `node packages/content-tools/src/cli.ts schema <куда>` пишет `bank.schema.json`, `questions.schema.json`, `node.schema.json` и `catalog.schema.json`.
