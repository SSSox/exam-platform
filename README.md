# Экзаменатор

Приложение для подготовки к экзаменам по тестовым банкам вопросов. Студент выбирает свой семестр, берёт предмет и тренируется: отвечает, сразу видит разбор, возвращается к ошибкам. Перед экзаменом можно прогнать пробный тест с таймером.

Код не привязан к вузам и дисциплинам. Дерево разделов и вопросы лежат в обычных JSON-файлах отдельного репозитория банков. Чтобы добавить предмет или целый вуз, меняют данные. Адрес репозитория банков записан в `content-sources.json`: по нему приложение подтягивает банки по сети, и пересобирать его при правке банков не нужно. Встроенный снимок остаётся запасным источником. Работают версии для Windows и Android (Tauri) и веб-версия (статическая сборка, подходит для GitHub Pages).

Это репозиторий кода. Реальных банков в нём нет, только небольшой демо-набор в `examples/demo-content`.

## Что умеет приложение

- Каталог из дерева любой глубины: университет, факультет, степень, специальность, курс, учебный год, семестр, предмет. Студент выбирает свой семестр один раз, приложение запоминает выбор на устройстве и при запуске сразу открывает его. Папки с единственной записью приложение пропускает, пока не встретится выбор из двух и более. Выбор можно сменить кнопкой «Сменить» или забыть в настройках («Забыть стартовый раздел»): ответы и прогресс при этом остаются. Там же кнопка «Удалить все данные» стирает с устройства ответы, настройки и скачанные банки (после подтверждения).
- Предмет может быть группой банков, например с уровнями внутри.
- Два режима ответа: выбор варианта и ввод с клавиатуры. Вопросы, на которые нельзя ответить вводом, приложение предлагает в режиме самопроверки (показать ответ и отметить, знал ли его) или пропускает, как задано в настройках.
- Тренировка с разбором после каждого ответа и пробный экзамен с таймером. В экзамене к любому вопросу можно перейти по номеру. Разбор экзамена появляется после завершения, порог зачёта 50 %. Начатый экзамен не пропадает, если перезагрузить страницу или закрыть приложение: при следующем запуске он откроется на том же вопросе, с теми же ответами, а время продолжит идти по часам.
- Отбор вопросов по темам, уровню сложности и количеству. Отдельно можно повторить только ошибки или только закладки. «Умный подбор» берёт сначала ошибки и вопросы, которым подошёл срок повторения, затем новые, и чаще возвращает те, где студент ошибался.
- Одного верного ответа мало, чтобы ошибка исчезла. В тренировке вопрос, в котором студент ошибся, возвращается в тот же подход через три вопроса; если повтор оказался верным, ещё раз через шесть. Так идёт, пока студент не ответит верно два раза подряд, но не больше четырёх возвратов одного вопроса за подход. Один и тот же вопрос не идёт дважды подряд.
- Повторение с интервалами между подходами: верный ответ откладывает вопрос на 8 часов, 2, 5, 12 и 30 дней, ошибка возвращает его в начало. Ответ раньше срока вопрос не продвигает. Интервал в 30 дней открывается только ответам вводом или самопроверкой, при выборе вариантов потолок 12 дней.
- Статистика освоения: вопрос считается освоенным, когда студент ответил на него верно в разные дни и не успел забыть. Процент освоения считается по каждой теме и по банку: чем дальше вопрос продвинулся по интервалам, тем больше он даёт, а просроченный повтор вес снижает. Это оценка, а не гарантия.
- Типы вопросов: один или несколько вариантов, короткий текст, число с допуском, развёрнутый ответ с критериями. В формулировках работают Markdown и формулы KaTeX.
- Проверка введённого ответа не учитывает регистр, пунктуацию, падежные окончания, латинские буквы-двойники в русском слове и одну-две опечатки в длинных словах. Другой термин из того же банка она не засчитывает. Если приложение ошиблось, ответ можно оспорить.
- Карта вопросов по темам. Каждый вопрос на ней квадрат, на который можно нажать: откроется окно с текстом вопроса, статистикой ответов, кнопками «Ответить», «Показать ответ» и «В закладки» и стрелками к соседним вопросам. Пять состояний (не начат, в работе, ошибка, освоен выбором, освоен вводом) отличаются цветом и формой, а метка «пора повторить» стоит на любом из них. Строки легенды работают как фильтр. Рядом с картой статистика по режимам, закладки и список ошибок. Журнал прогресса выгружается в файл и загружается обратно, так что его можно перенести на другое устройство.
- Интерфейс на трёх языках: kk, ru, en. Язык вопросов выбирается отдельно: если перевода нет, вопрос показывается на языке оригинала. Тема оформления: системная, светлая или тёмная.
- Работа без сети: прочитанные файлы контента кэшируются, а копия контента лежит внутри приложения.
- Веб-версия ведёт к приложениям: под списком предметов и в настройках есть ссылки на установщики для Windows и Android. В самих приложениях этих ссылок нет.
- Приложения для Windows и Android обновляются из релизов на GitHub: раз в день проверяют, вышла ли новая версия, а по кнопке «Обновить» скачивают её, проверяют подпись и ставят поверх старой. Ответы и настройки остаются.

## Как это устроено

Два репозитория с разными задачами:

| Репозиторий | Что в нём | Как меняется |
| --- | --- | --- |
| Код (этот) | приложение, схема формата, проверка ответов, командная строка для работы с контентом | разработчиком |
| Банки (например, `exam-content`) | дерево папок с `node.json`, банки `bank.json`, вопросы, переводы | редакторами контента |

Банки публикуются отдельно: команда `compile` превращает дерево папок в набор файлов, где имя каждого файла содержит хэш его содержимого (`index.json`, `nodes/<хэш>.json`, `banks/<хэш>.json`). Этот набор выкладывают на любой статический хостинг, например GitHub Pages. Приложение читает `index.json`, скачивает только изменившиеся файлы, сверяет хэш каждого и кэширует их навсегда.

Откуда приложение берёт банки:

1. `index.json` скачивается с сетевых адресов из `content-sources.json` по очереди (`VITE_CONTENT_URLS` через запятую заменяет их на одну сборку). Адрес, который не ответил за 6 секунд, пропускается.
2. Без сети берётся последний сохранённый `index.json`, а при самом первом запуске встроенный снимок `./content`, если он есть в сборке. В обоих случаях приложение пишет, что сети нет.
3. Файл банка ищется сначала в кэше, потом во встроенном снимке и только потом в сети, так что банк, пришедший вместе с приложением, открывается без запроса. Файлы, на которые свежий `index.json` больше не ссылается, удаляются из кэша.

Вся логика в `packages/core` не зависит от оболочки: интерфейс и Tauri только показывают её. Прогресс хранится как журнал событий, к которому только дописывают, и журналы с двух устройств сливаются без конфликтов.

## Требования

- Node.js 26 (на нём проверялось). Скрипты запускаются как `.ts` без отдельной сборки.
- npm. Проект использует npm workspaces.
- Для установщика Windows нужен Rust и системные зависимости Tauri 2 (см. документацию Tauri).
- Для Android нужны Rust с целью `aarch64-linux-android` (для эмулятора ещё `x86_64-linux-android`), JDK 21 (не новее), Android SDK с платформой 37 и NDK 28. Пути задаются переменными `JAVA_HOME`, `ANDROID_HOME` и `NDK_HOME`.

## Быстрый старт

```bash
npm install
npm --prefix apps/ui run dev
```

Интерфейс откроется на `http://localhost:5183`. Перед запуском скрипт `apps/ui/scripts/content.mjs` собирает контент в `apps/ui/public/content`. Источник выбирается так:

1. Папка из переменной `EXAM_CONTENT_DIR`, если она задана. Значение `none` ничего не встраивает, и приложение берёт банки только по сети.
2. Папка `exam-content` рядом с этим репозиторием, если в ней есть `catalog.json`.
3. `examples/demo-content` из этого репозитория.

Если рядом нет папки `exam-content` и переменная не задана, вы увидите демо-контент: пять небольших банков двух специальностей «Демо-университета».

Переменные задаются перед командой. В bash:

```bash
EXAM_CONTENT_DIR=/путь/к/банкам npm --prefix apps/ui run dev
```

В PowerShell:

```powershell
$env:EXAM_CONTENT_DIR = "C:\путь\к\банкам"; npm --prefix apps/ui run dev
```

Относительный путь считается от папки, где запущен npm, поэтому надёжнее абсолютный.

## Подключение репозитория банков

Приложение берёт банки из репозитория, опубликованного как статический сайт. Адрес сайта передаётся при сборке:

```bash
EXAM_CONTENT_DIR=none VITE_CONTENT_URLS=https://<пользователь>.github.io/<репозиторий-банков> npm --prefix apps/ui run build
```

Здесь `EXAM_CONTENT_DIR=none` убирает встроенный снимок, а `VITE_CONTENT_URLS` указывает, откуда качать. Можно перечислить несколько адресов через запятую: приложение пробует их по очереди. Снимка в такой сборке нет, поэтому без сети она показывает только то, что уже скачано. Переменную можно сохранить и в файле `apps/ui/.env.local` (он не попадает в git):

```
VITE_CONTENT_URLS=https://<пользователь>.github.io/<репозиторий-банков>
```

Адрес в примере условный: подставьте адрес своего репозитория банков. В PowerShell переменные задаются через `$env:`, как в примере выше. Страница приложения загружает контент только с `https://*.github.io` и `https://cdn.jsdelivr.net`. Если банки лежат на другом хосте, добавьте его в `connect-src` в `apps/ui/index.html`.

Пошаговая публикация приложения и банков, вместе с шаблонами workflow для GitHub Actions: [docs/PUBLISHING.md](docs/PUBLISHING.md).

## Сборка

Статическая сборка интерфейса попадает в `apps/ui/dist`:

```bash
npm --prefix apps/ui run build
```

Пути в сборке относительные, поэтому она работает на веб-хостинге, в подпапке и внутри Tauri.

Установщик для Windows (NSIS), сборка долгая:

```bash
cd apps/desktop
npx tauri build
```

APK для Android (нужны переменные `JAVA_HOME`, `ANDROID_HOME`, `NDK_HOME` из раздела «Требования»). Телефонам хватает цели `aarch64`, APK выходит около 9 МБ. Для эмулятора x86_64 добавьте `--target x86_64`.

```bash
cd apps/desktop
npx tauri android build --apk --target aarch64
```

Релизный APK подписывается ключом из файла `src-tauri/gen/android/keystore.properties`. Git этот файл не видит, образец лежит рядом: `keystore.properties.example`. Скопируйте его и впишите полный путь к файлу ключа (`.jks` или `.keystore`, через `/`, без `~`) и псевдоним ключа. Пароли можно вписать туда же или задать на время сборки переменными `KEYSTORE_PASSWORD` и `KEY_PASSWORD`. Подписанный файл появится в `src-tauri/gen/android/app/build/outputs/apk/universal/release/app-universal-release.apk`. Без `keystore.properties` сборка оставляет APK неподписанным (`app-universal-release-unsigned.apk`), и телефон его не установит.

Если ключа ещё нет, его создаёт `keytool` из JDK:

```bash
keytool -genkeypair -keystore "$HOME/exam-trainer-release.jks" -alias exam-trainer -keyalg RSA -keysize 4096 -validity 10000
```

Держите ключ и пароли вне репозитория и сохраните их резервную копию. Новая версия ставится поверх старой, только если подписана тем же ключом. После смены ключа приложение придётся удалить, а с ним пропадёт прогресс: он хранится только на телефоне, перенести его можно файлом прогресса. При установке файла вручную телефон попросит разрешить установку из этого источника. Прогресс на Android сохраняется и загружается через системный диалог выбора файла.

Окно настольного приложения в режиме разработки: `npx tauri dev` из той же папки. Сборка Tauri запускает сборку интерфейса, поэтому переменные `EXAM_CONTENT_DIR` и `VITE_CONTENT_URLS` действуют и на неё.

Адреса ссылок на установщики веб-версия берёт при сборке из `downloads.json` (поля `windows` и `android`). Переменные `VITE_DOWNLOAD_WINDOWS` и `VITE_DOWNLOAD_ANDROID` заменяют их на одну сборку, значение `none` убирает ссылку, а адрес, который не начинается с `https://`, останавливает сборку. По умолчанию ссылки ведут на файлы последнего релиза репозитория кода на GitHub, выпуск релиза описан в [docs/PUBLISHING.md](docs/PUBLISHING.md).

Чтобы приложения обновлялись сами, в `plugins.updater.pubkey` в `tauri.conf.json` вписывается открытый ключ обновлений, а релиз готовит команда `npm run release`: она подписывает установщик и APK и пишет `latest.json`. Ключ и выпуск описаны там же, в [docs/PUBLISHING.md](docs/PUBLISHING.md).

## Работа с контентом

Командная строка лежит в `packages/content-tools`:

```bash
node packages/content-tools/src/cli.ts <команда> ...
```

В корне репозитория есть сокращение `npm run content -- <команда> ...`.

| Команда | Что делает |
| --- | --- |
| `validate <папка-контента>` | проверяет раскладку папок, схемы, повторы идентификаторов, ключи и блоки свободного ввода |
| `compile <папка-контента> <куда>` | собирает файлы с хэшами в именах для приложения |
| `merge-translations <папка-контента>` | вливает переводы из `translations/` в банки |
| `schema <куда>` | записывает JSON Schema формата |
| `migrate <v1.json> <id-банка> <папка-банка>` | переводит банк формата 1.0 в `exambank/2` |
| `verify <v1.json> <папка-банка>` | собирает банк обратно в формат 1.0 и сравнивает с исходным файлом |

Проверить демо-контент:

```bash
npm run content -- validate examples/demo-content
```

Команда напечатает число банков и вопросов. Формат, раскладка папок, правила идентификаторов и переводов описаны в [docs/FORMAT.md](docs/FORMAT.md).

- Идентификатор банка (`id` в `bank.json`) никогда не меняется: на него ссылается прогресс студентов. Банк можно переименовывать и переносить между папками, пока `id` остаётся прежним.
- Идентификатор вопроса не меняется и не используется повторно. Ненужный вопрос помечают `"retired": true`.
- Переводы кладут в `<банк>/translations/<локаль>/` и вливают командой `merge-translations`. Исходный язык банка в переводах не правится.

## Структура репозитория

```
packages/
  schema/             Zod-схемы формата
  core/               проверка ответов, сессии, прогресс, память и подбор вопросов, клиент контента, обход дерева
  content-tools/      командная строка и функции validate, compile, merge, migrate
apps/
  ui/                 интерфейс: React 19, Vite
  desktop/            оболочка Windows и Android: Tauri 2
examples/
  demo-content/       нейтральный демо-репозиторий банков
.github/workflows/
  release.yml         сборка и подпись установщика Windows в GitHub Actions
.signpath/            настройки подписи для SignPath
docs/
  FORMAT.md           формат exambank/2 и раскладка папок
  PUBLISHING.md       публикация на GitHub Pages и выпуск релизов
content-sources.json  адреса сайта с банками
downloads.json        ссылки веб-версии на установщики
```

## Проверки

```bash
npx vitest run     # тесты: схема, проверка ответов, сессии, прогресс, повторение и подбор, контент, переводы, обход дерева
npx tsc -p .       # типы: пакеты и интерфейс
```

Тесты используют `examples/demo-content` и пишут только во временные папки. Интерфейс автотестами не покрыт: после правок его проходят в браузере вручную.

## Политика подписи кода (Code signing policy)

Сейчас установщик для Windows не подписан сертификатом издателя, и SmartScreen может предупредить о неизвестном издателе. Проект подаёт заявку на бесплатную подпись через [SignPath Foundation](https://signpath.org).

Подписываться будут только файлы, которые GitHub Actions собирает из этого репозитория ([`release.yml`](.github/workflows/release.yml)): приложение `exam-desktop.exe` и установщик. Программа удаления, которую создаёт NSIS, отдельной подписи не получает. APK для Android подписывается ключом разработчика, а не через SignPath.

- Авторы и проверка изменений: [SSSox](https://github.com/SSSox).
- Подтверждение каждой подписи: [SSSox](https://github.com/SSSox).
- Приватность: приложение не передаёт сведений о пользователе. По сети оно только скачивает банки вопросов с GitHub Pages (адреса из `content-sources.json`) и проверяет обновления в релизах на GitHub. Ответы, прогресс и настройки остаются на устройстве. На эти запросы действует [политика конфиденциальности GitHub](https://docs.github.com/site-policy/privacy-policies/github-general-privacy-statement).
